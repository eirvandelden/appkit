# Changelog

**Note:** This project uses git SHAs instead of semver. Pin to a specific SHA in your Gemfile.

## Unreleased

### Added
- Engine skeleton and dummy-app test harness (Task 0). No auth/PWA/theme features yet.
- Session-based authentication: login/logout, session cookie, configurable `email_attribute`/`user_scope` (Task 1).
- FirstRun bootstrap, session transfer + QR magic-link handoff, `VersionHeaders`, `Authorization`, static error pages via the install generator, and `Authenticatable#deactivate!` (Task 1b). Portions adapted from Basecamp's Writebook (MIT) — see `THIRD_PARTY_NOTICES.md`.
- Theme/preferences: `UserTheming` concern (`color_scheme`/`light_theme`/`dark_theme` enums), `ThemeHelper`, Stimulus `theme_controller.js`, `PreferencesController`/view with an optional `config.timezone_attribute` gate, a reusable `_flashes` partial, and `en`/`nl`/`it` locale files covering sessions/first_run/preferences (Task 3).
- `Appkit::Menu`, `Appkit::Menu::Hub`, `Appkit::Menu::Page` and `Appkit::Menu::Link`: one menu map that places a request in a hub and a page, carries the origin in a `from` query parameter, and gives the back link and the exit path. A hub can sit under a parent hub (`parent:`): it has no rail item, and the rail marks the parent while it is current. A page can be a submit page (`verb: :delete`, for example sign-out): its tile and hub-column item send that request, and search leaves it out. A list origin (`from=<hub>.<page>`, written by `Menu#carry_list` and parsed by `Appkit::Menu::Origin`) brings a record back to the list it was opened from. `Appkit::MenuHelper#menu_entry_to` renders a tile or hub-column entry as a link, with `data-turbo-method` for a submit page.
- Type signatures: appkit ships RBS in `sig/`, generated from inline `#:` comments with `rbs-inline`, and checks its own code with Steep. A type-checking app can drop its appkit stub or `@type const` workaround; a hand-written appkit stub left in place makes Steep report duplicate declarations.
- A host app without the `mvpa-css` co-gem now fails at boot with `Appkit::MissingCoGem`, which names the `Gemfile` line to add. Appkit requires mvpa-css itself, so it loads before `Appkit::Engine` whatever the `Gemfile` order or `require:` option.

### Changed
- The `login` layout now renders its flashes as a direct child of `<body>`, above `<main>`. mvpa-css treats `main` as a size container, so flashes inside it scrolled with the content on Safari before 18.4.
- appkit now requires Rails 8.1: the gemspec floors are railties `~> 8.1`, turbo-rails `~> 2.0`, importmap-rails `~> 2.2`, web-push `~> 3.1`, rqrcode `~> 3.2` and okcomputer `~> 1.20`, so apps on Rails 8.0 can no longer install appkit.
- The reusable `rails-ci.yml` workflow now uses `actions/checkout@v7`, `actions/cache@v6` and `actions/setup-node@v7`. Checkout v7 refuses to check out a fork's pull request under `pull_request_target` or `workflow_run`, so an app that calls `rails-ci.yml` from one of those triggers fails on fork pull requests.
- The reusable `rails-ci.yml` test job now runs `npm ci` when the calling app has a `package-lock.json`. Apps without that file are unaffected.
- The reusable `rails-ci.yml` `scan_js` and `lint` jobs now run on `ubuntu-latest` instead of `ubuntu-slim`, whose libcrypto lacks `OPENSSL_3.4.0` and could not load `openssl` 4.0.2. Both jobs failed at boot before this change. Apps need not act.
- The reusable `rails-ci.yml` `scan_ruby` job now runs on `ubuntu-latest` instead of `ubuntu-slim`, where `bin/brakeman` failed with `OpenSSL is not available`. Apps need not act.
- The `appkit/shared/nav` partial now renders a rail of task hubs and a hub column for the current hub, from an `Appkit::Menu` map. It has no account menu: the host builds an account hub from pages, with a sign-out submit page. It no longer renders the app-name heading, the home link, the yielded list items or the Voorkeuren link. The `appkit.navigation.home` locale key is gone; `appkit.navigation.rail` and `appkit.navigation.hub_column` are new.

### Fixed
- `app_name` accepts a string or a callable, as the README shows, instead of crashing the sign-in page, first-run page, nav, login page title and PWA manifest with `NoMethodError`. A blank or unset name falls back to the host application module name, and a top-level `app_name` locale key gives a translated name per locale. The PWA manifest now follows the request locale. To do that, the manifest and the service worker now inherit the host's `ApplicationController`, so every host `before_action` runs on them, including a Rails 8 host's `allow_browser versions: :modern`. Both endpoints now send `Cache-Control: max-age=0, private, must-revalidate` instead of `no-cache`, so a CDN or proxy no longer caches them.
- The service worker cache name now changes with every appkit commit, also in hosts whose Docker build deletes the gem's `.git` directory.
- Following the README or running `bin/rails generate appkit:install` no longer leaves engine pages raising `NoMethodError` for `allow_unauthenticated_access`: the generator adds `include Appkit::Authentication` to `ApplicationController`.

### Upgrading
1. Upgrade the app to Rails 8.1 before you move its appkit pin to this SHA. Bundler does not resolve appkit next to Rails 8.0.
2. If the app calls `rails-ci.yml` from a `pull_request_target` or `workflow_run` trigger, move that call to `pull_request`. Otherwise checkout v7 fails on fork pull requests.
3. Check that no `before_action` in your `ApplicationController` redirects or blocks `GET /manifest` or `GET /service-worker`; both now inherit it.
4. If your `ApplicationController` does not include `Appkit::Authentication`, add `include Appkit::Authentication` to it by hand. Do not re-run `bin/rails generate appkit:install` for this: in an app that has a `sessions` table, it also creates an `align_sessions_for_appkit` migration.
5. Add `gem "mvpa-css", github: "eirvandelden/mvpa.css"` to the app's `Gemfile` and run `bundle install`. Without it the app no longer boots.
6. If the app overrides `app/views/layouts/login.html.erb`, move `<%= render "appkit/shared/flashes" %>` out of `<main>` to a direct child of `<body>`, above `<main>`.
7. Build an `Appkit::Menu` per request from your own map of hubs and pages: `Appkit::Menu.new(hubs:, controller_path: controller_path, params: request.parameters)`. Each `Appkit::Menu::Hub` takes a `landing:` hash (a controller path plus params) and its `pages:`; a hub may hold only one page per controller. Give a hub that has no rail item of its own `parent: <key of a rail hub>`: it still gets its hub column, and the rail marks its parent while it is current. A parent must be a rail hub in the map, or `Appkit::Menu.new` raises `ArgumentError`. Expose the menu to views, for example with `helper_method :menu`.
8. Render the nav with `render layout: "appkit/shared/nav", locals: { menu: menu } do … end`, as the only content of `<body> > <header>`; mvpa.css lays out the shell from that header. The block renders at the top of the rail: put the search button there. Put the Voorkeuren page and a sign-out submit page in an account hub of your own, for example a 👤 rail hub with the pages `Appkit::Menu::Page.new(key: :preferences, label: t("appkit.navigation.preferences"), path: edit_preferences_path, controllers: [ "appkit/preferences" ])` and, last, `Appkit::Menu::Page.new(key: :sign_out, label: t("appkit.navigation.logout"), path: session_path, controllers: [], verb: :delete)`.
9. On each hub's landing page, link every tile with `menu_entry_to menu.tile_path(page), page do … end`, so a submit page's tile sends its request. That href carries the hub as the origin in a `from` query parameter. Link a list's records with `menu.carry_list(path)`, so a record returns to the list it was opened from. Within the flow, pass the origin on with `menu.carry(path)` in links, `menu.origin_params` in `button_to` params and `hidden_field_tag :from, menu.origin_key` in forms. Render `menu.back(fallback)` as the title-bar back link, as the first item of `main > header nav`: it returns an `Appkit::Menu::Link` or `nil`, and the host writes the label, for example `link_to "‹ #{back.label}", back.path`. Redirect to `menu.exit_path(fallback)` after a delete.
10. Stop relying on the old home link, the app-name heading and the yielded `<li>` items: the nav no longer renders them. Use the `appkit.navigation.home` key no more; it is removed.
11. Move `mvpa-css` in your `Gemfile` to a commit whose CHANGELOG names the rail and hub column. Before that, the new nav renders as plain lists, and a page with a hub column lays out differently from a page with only the rail.
12. If your app already passes `account:` to `Appkit::Menu.new`, remove it, and turn each account link into a page of a rail hub of your own, as in step 8.
13. Replace every `rail: false` on an `Appkit::Menu::Hub` with `parent: <key of the rail hub that should light up>`.
14. Add the sign-out submit page last to that account hub, as in step 8.
15. Render landing tiles with `menu_entry_to menu.tile_path(page), page do … end` instead of `link_to`, as in step 9.
16. Drop `user_name:` from the `appkit/shared/nav` locals, and delete every `render "appkit/shared/account_menu"`: the partial is gone.
17. Load Turbo on every page that renders the nav: pin it with `pin "@hotwired/turbo-rails", to: "turbo.min.js"` in `config/importmap.rb`, import it with `import "@hotwired/turbo-rails"` in `app/javascript/application.js`, and render `<%= javascript_importmap_tags %>` in the layout. Also render `<%= csrf_meta_tags %>` in the layout `<head>`: Turbo sends that token with a submit page's request, and without it sign-out fails with `ActionController::InvalidAuthenticityToken`. Without Turbo, a submit page's link sends GET and fails.
